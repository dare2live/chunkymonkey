## 0. 一句话

把任一股任一时点的 K 线, 先粗分 **上涨/横盘/下跌** 三大类, 再逐层细化到形态、子态, 直至穷尽覆盖;
核心精细化手段 = **行为 × 位置 上下文消歧**(同样的价量行为, 在高位/低位/中继是不同形态)。

---

## 1. 设计原则 (验收标尺)

1. **第一性**: K线价/量是真相源, 形态 = 价/量/位置的可量化模式; 不引入派生中间表。
2. **分层穷尽**: 先 3 大类, 逐层下钻, 每 bar 必有归属(或显式"待确认/过渡"), 无遗漏无重叠。
3. **上下文消歧 (用户核心洞察, 研究已验证)**: 同一价量行为按**位置(价格分位)+前序趋势**区分含义。
   研究实证: "缩量上涨"被 5+ 理论指为"位置无关一刀切=方向冲突" → 必须位置化。
4. **config 驱动 / 可解释 / 可溯源**: 形态结构与参数全进 config; 每态带**理论锚定**(provenance)。
5. **软隶属 + 多TF + PIT**: 软隶属度(一股可部分属多态); 日/周/月; 特征/上下文只用 ≤t。
6. **无偏差可见**: 每个形态都被充分识别(无某态塌缩为 0), 否则形态不可见 = 偏差。

## 2. 分层结构 (L1 → L2 → L3 + 边界事件 + 正交维度)

### L1 — 趋势大类 (3, 用户指定)
| 大类 | 判据(价相对中长均线 + 动量符号 + 斜率) |
|---|---|
| 上涨 | 价在均线上 + 动量正 + 斜率正 |
| 横盘 | 斜率近0 + 窄幅 + 动量近0 |
| 下跌 | 价在均线下 + 动量负 + 斜率负 |

### L2 — 形态 (行为 × 位置 细分; 含新增态)
| L1 | L2 形态 | 性格 | 理论锚定 |
|---|---|---|---|
| 上涨 | 放量突破 | 低位放量+大涨+上穿 (起涨) | Wyckoff SOS / O'Neil pivot / Weinstein 1→2 |
| 上涨 | 上升通道 | 均线向上+多头排列 (主升) | Weinstein Stage2 / 道氏上升 |
| 上涨 | 缩量上涨 ⚠位置消歧 | 价涨量缩 | 高位=衰竭(No Demand) / 低位=弱反弹(空涨) |
| 横盘 | 低位横盘 | 低位+窄幅+地量 (筑底) | Wyckoff Accumulation / Weinstein Stage1 |
| 横盘 | **中继平台 (新)** | 中位+窄幅+主力清洗 (主升中继) | 中文主升浪中继 / O'Neil base-on-base |
| 横盘 | 高位滞涨 | 高位+涨势停滞 (派发) | Wyckoff Distribution / Weinstein Stage3 |
| 下跌 | 下跌通道 | 均线向下+无量阴跌 (主跌) | Weinstein Stage4 / 道氏下降 |
| 下跌 | **放量下跌 (新, 3位置消歧)** | 价跌+放量 | 见 §3 (用户核心例子) |
| 下跌 | 缩量回踩 | 升势中小幅缩量回调 (健康) | Minervini VCP / 道氏次级回调 |

### L3 — 子态 (修饰量: 路径效率/回撤/加速/量能z)
- 上升通道 → 温和 / 震荡 / 加速上涨
- 低位横盘 → 地量 / 温和; (待评审: cup-handle/flat-base/double-bottom 几何细分)
- 放量突破 → 温和 / 巨量
- 高位滞涨 → 放量派发(BC) / 缩量惜售
- 下跌通道 → 温和阴跌 / 加速杀跌
- 缩量回踩 → 浅 / 深
- 放量下跌 → 见 §3

### 边界事件 (cross-cutting, 标在 L2 转换处 — 用户"形态的边界")
> 这些是**离散转换事件**, 需短序列逻辑(对比近 N bar), 非逐 bar 瞬时态。研究列为高优盲点。
- **假突破** (Upthrust/UTAD/2B): 突破后 N 日跌回突破位 (诱多陷阱) → 看空
- **挖坑洗盘** (Spring/Shakeout): 跌破前低后 N 日收回区间 (诱空陷阱) → 看多
- **量价背离** (effort-vs-result / No Demand / No Supply): 量价不匹配
- **选择性高潮** (Selling Climax 底 / Buying Climax 顶): 极端放量拐点
- **待确认缓冲** (hysteresis deadband + N-bar confirm): 转换需收盘确认 + 双阈值死区

### 正交维度 (置信度乘子, 不改主态)
- **相对强度 RS** (vs 大盘/行业): RS 升破/跌破零轴 → 置信度乘子 (研究高优盲点)
- **base-stage 计数** (第几个底/浪)

## 3. 精细化识别 — 上下文消歧 (用户核心例子)

**放量下跌 = 价跌 + 放量, 但位置不同含义全反:**

| 精细态 | 位置(pctile) | 前序趋势 | 含义 | 理论 | 决策 |
|---|---|---|---|---|---|
| **高位放量下跌** | 高 (>0.7) | 前序上涨 | 顶部破位/出货 breakdown | Wyckoff Distribution / SOW | 看空, **鱼尾出场** |
| **低位放量下跌** | 低 (<0.3) | 前序下跌 | 恐慌抛售/Selling Climax | Wyckoff SC / VSA Stopping Vol | 可能见底, **反转预警** |
| **下跌中继放量** | 中 (0.3-0.7) | 下跌通道中 | 破位加速/趋势延续 | 道氏主跌 / 缠论下跌中继 | 延续, 规避 |

**同理其他行为位置化:**
- 缩量上涨: 高位=衰竭背离(看空) / 低位=无量弱反弹(不追)
- 横盘: 低位=筑底(蓄势) / 中位=中继(清洗) / 高位=派发(出货)
- 缩量(下跌中): 升势中=健康回踩(可持) / 跌势中=阴跌延续(规避)

**消歧维度 = 价格分位(瞬时位置) + 前序态(as-of, PIT)。** 这是"精细化"的本质:
不是加更多瞬时阈值, 而是引入**位置/上下文**把同一行为分裂成多个语义。

## 3.5 识别尺度 (短/中/长期 + 单日裸K线 — 用户扩展)

> 形态识别是**多尺度**的: 同一股在不同时间窗呈现不同形态, 且最细到**单根 K 线**也有形态。
> 尺度维度与 L1/L2/L3 行为维度**正交**: 每个尺度都跑完整 L1→L2→L3 + 命名形态。

| 尺度 | 窗口 | 识别内容 | 量化方式 |
|---|---|---|---|
| **单日** (single bar) | 1 日 | 单根 K 线解剖形态 | 开高低收几何 (实体/影线比例) |
| **短期** (short) | 3-10 日 | K 线组合形态 | 近 N 根价量序列模式 |
| **中期** (medium) | 20-60 日 | 形态/通道/图表形态 | 现有 L2 态 + 经典图表形态 |
| **长期** (long) | 季度+ (周/月线) | 趋势阶段 | L1 + Weinstein 4 阶段 / Wyckoff 4 相 |

现有多TF(日/周/月)≈ 中/长期; 需**新增 单日 + 短期(K线组合)** 两个更细尺度。

## 3.6 命名形态词汇层 (中文/英文实战术语 — 用户扩展)

> 实战用的是**命名形态**(老鸭头/十字星/cup-handle), 不是抽象态。命名形态 = 量化态/事件/几何的**可解释标签**,
> 让档案"说人话"。命名层叠加在量化层上 (人话词汇 ↔ 量化条件), config 化 (新增/改命名形态=改config)。

| 尺度 | 中文命名 | 英文命名 | 映射到量化 |
|---|---|---|---|
| 单日 | 大阳/大阴线·十字星·锤子线·上吊线·长上下影·光头光脚·纺锤 | marubozu·doji·hammer·hanging man·long shadow·spinning top | 单K几何 (实体%/上影%/下影%) |
| 短期 | 红三兵·黑三兵·早晨之星·黄昏之星·乌云盖顶·旭日东升·吞没·仙人指路·穿头破脚 | three soldiers·morning/evening star·dark cloud·engulfing·piercing | 近2-5根价量序列模式 |
| 中期 | 老鸭头·头肩顶/底·双顶/双底·圆弧底·旗形·三角形·平台突破·箱体 | cup-handle·head&shoulders·double top/bottom·flag·triangle·rounding bottom | L2态序列 + 几何 (颈线/把手/对称) |
| 长期 | 四阶段(吸筹/拉升/派发/下跌)·缠论级别 | Weinstein 4 stages·Wyckoff phases | L1 + 阶段序列 |

**老鸭头示例 (复合命名形态 = 态序列匹配)**: 上升通道(头部)→缩量回踩(鸭脖)→低位/中继横盘(鸭头)→放量突破60日线(鸭嘴张开/出水) — 是一个**态序列模板**, 不是单态。
命名形态识别 = (a) 量化层先出态/事件/单K几何; (b) 命名层用**模板匹配**(序列/几何规则, config 化)给人话标签。

## 4. 识别方法 (recognition)

1. 特征 (PIT, ≤t): 均线斜率/多头排列/动量/价格分位/区间宽度/量比/距均线 + 路径效率/R²/加速/回撤/量能z。
2. **位置/上下文特征 (新)**: 价格分位(已有) + 前序主态(as-of, 近K根的 dominant) + 距前高/前低。
3. L2 形态 = 声明式 config 条件 (指标/判断/阈值/锐度) → sigmoid 软门取积 → softmax 软隶属 → dominant。
4. L3 子态 = 主态 × 修饰量分位。
5. 边界事件 = 短序列检测器 (近 N bar 价量序列模式), 叠加在 L2 之上 (overlay, 非互斥态)。
6. 多TF: 日主 + 周/月确认 (mtf_aligned); 上下文消歧在每 TF 内独立算。

## 5. 覆盖完整性验证 (怎么证明"穷尽")

- **归属率**: 每 bar 归入某 L2 (或"待确认") 的比例 → 目标 ≥95% covered。
- **转换矩阵**: 相邻日主态转换矩阵对角占优 (态稳定不乱跳) + 转换符合生命周期序列 (筑底→突破→主升→滞涨→下跌)。
- **无偏差**: 每个 L2 态在全宇宙都有非平凡占比 (无塌缩) → 形态可见。
- **语义抽查**: 已知案例 (主升浪股/崩盘股/筑底股) 分类与人工/理论一致。
- **理论锚定全覆盖**: 每态都有 ≥1 理论 provenance; 研究列的高优盲点都有对应态/事件或显式记 deferred。

## 6. 工具化 / 模块化 / 配置化 (用户强调: 硬约束)

> 复杂度上来后(9+态×位置×尺度×命名形态)**绝不堆 monolith**。每个关注点 = 独立单一职责模块, 全 config 驱动,
> 各有干净接口 + 单测 + PIT安全。加 态/事件/命名形态 = 加 config + (必要时)加模块, 不动既有、不 hardcode。

### 模块分解 (单一职责, 各读同一 config)
```
backend/services/technical_states/
├── features.py     特征计算 (PIT, 多尺度窗口: 单日/短/中/长)            [存在]
├── classifier.py   L1派生 / L2软隶属态 / L3子态 (声明式config解释器)    [存在, 扩展]
├── context.py  新  上下文消歧 (位置pctile × 前序态as-of → 同行为分流)
├── events.py   新  边界事件检测器 (假突破/挖坑/climax/背离, 短序列, overlay)
├── candles.py  新  单日K线形态 (十字星/锤子/光头光脚, 开高低收几何)
├── patterns.py 新  命名形态模板匹配 (老鸭头/头肩/cup-handle, 态序列规则)
├── coupling.py     边界耦合 resolver                                  [存在]
└── presets.py  新  Optuna预设管理 (最佳+次优, 加载/对比)
config/technical_states.yaml  全judgment参数: 层级树/状态条件/事件参数/单K阈值/命名模板/预设/provenance
```
**编排**: classifier 是 orchestrator — features → L1/L2/L3 + context 消歧; events/candles/patterns 作为 overlay 并列; dossier 聚合层组装成档案维度①。模块间**零循环依赖**, 只 classifier 编排。

### 接口契约 (每模块统一)
- 输入: PIT 特征/bars + config; 输出: 结构化 dict (态/事件/形态 + 置信度 + 人话描述 + provenance)。
- 纯函数优先 (可单测, 不碰 DB/全局); DB/IO 留 dossier 服务层。

### 管理 (config 化 + 版本 + 溯源 + 隔离)
- **判断全进 yaml**: 阈值/锐度/序列窗/模板规则/预设, 业务码只读 config (宪法 §1.0)。
- **版本+provenance**: config meta.version + 每态 theory_anchor (理论溯源) + 每预设 tuned_by (Optuna study id)。
- **探索隔离**: Optuna 调参在 sandbox, 验证(无偏差+语义+OOS)后才 promote 进 config + backend/services + 单测; confirmed_by_owner 门。
- **门**: 每模块单测 (PIT无前瞻 + 语义 + 边界); moth 断言; check_rule_compliance (no hardcode)。

### 前端 (可选, 用户说不强求手调)
- 档案视图显示 L1/L2/L3 + 边界事件标记 + 命名形态标签 + 多尺度切换; 预设选择(最佳/次优)对比。

## 7. 参数方案 (Optuna — 用户要"最佳 + 2-3 套次优")

- sandbox Optuna 调全部 L2 态阈值 + k + τ + 子态分位 + 位置消歧阈值 + 边界事件参数。
- 产 **1 套最佳 + 2-3 套次优**, 每套:
  - 不同目标 (均衡分离×覆盖 / 高分离纯度 / 高覆盖 / 理论锚定预设[量比1.5x+底部时长门]);
  - **无偏差硬约束**: 每态占比 ≥ 阈值 (无塌缩), 否则该 trial 罚分;
  - 语义验证 (各态/子态平均特征符合定义) + 转换矩阵对角占优。
- 验证后 promote: 最佳→config 默认; 次优→config 预设(供后续分析对比)。confirmed_by_owner 待全验证。

## 8. 待评审的关键决策点 (给多 agent review)

1. **上下文消歧的 PIT 安全**: 用"前序主态(as-of 近K根 dominant)"做消歧, 会不会引入循环依赖/前瞻? 还是该用纯瞬时的 pctile + 距前高前低 (无前序态)?
2. **放量下跌 3 分**: 高/低/中位是 3 个独立 L2 态, 还是 1 个 L2 + 3 个位置 L3 子态? (影响软隶属维度数)
3. **边界事件 vs 状态**: 假突破/挖坑/climax 是离散事件 overlay (需序列逻辑), 怎么和逐 bar 软隶属共存不冲突? 序列检测的 PIT 与确认延迟?
4. **缩量上涨(有争议态)**: 拆成 高位缩量上涨(衰竭)+低位缩量上涨(弱) 两态, 还是保留 1 态 + 位置子态?
5. **缩量回踩归属**: 归"下跌"大类(价在跌) 还是"上涨"大类(升势中回调)? L1 派生口径。
6. **横盘三态边界**: 低位横盘 / 中继平台 / 高位滞涨 的 pctile 带如何切分不重叠不留缝 (留过渡带还是硬切)?
7. **确认门层级**: hysteresis/N-bar 确认加在分类层(改软隶属) 还是独立的状态序列层(FSM, 不改瞬时分类)?
8. **RS 正交维度**: 现在就加(需大盘相对数据接入) 还是后置? 影响"无偏差可见"吗?
9. **Optuna 无偏差约束量化**: "每态占比≥阈值"的阈值定多少? 市场真实分布本就不均(如下跌态多), 强制均衡会不会反而扭曲?
10. **覆盖穷尽的证明**: 转换矩阵 + 归属率够证"全覆盖"吗? 还是需要枚举所有"理论形态"清单逐一核对命中?
11. **多TF 的位置消歧**: 周/月线的"位置"与日线不同步, 三框消歧如何聚合?
12. **新增态的 over-fit 风险**: 9+态 × 位置消歧 × 边界事件, 参数空间膨胀, 会不会 in-sample 漂亮 OOS 崩? 怎么守 walk-forward?
13. **尺度 × 行为 笛卡尔积爆炸**: 4 尺度 × (L1/L2/L3) × 命名形态, 组合数巨大。哪些尺度真有独立价值, 哪些冗余? 单日 K线形态对中期主升浪选股有增量吗, 还是噪音?
14. **命名形态 = 模板匹配 vs 独立态**: 老鸭头/头肩顶 是"态序列模板匹配"(派生标签, 不进软隶属) 还是独立识别态? 模板规则 config 化到什么粒度? 命名形态的主观性(不同人画法不同)怎么量化锚定不偏?
15. **单日 K线形态的信息量**: 单根 K 线(十字星/锤子)PIT 干净但信息稀疏且噪音大, 单独用易过拟合。是只作为"短期组合"的构件, 还是也独立输出? A股单日±10%限制对单K形态(光头光脚=涨停)的特殊含义。
16. **命名形态与量化态的一致性**: 命名层(老鸭头)和量化层(态序列)若冲突(如量化判下跌但模板匹配老鸭头), 以谁为准? 命名形态置信度怎么定?

## 9. 评审产出要求

多 agent 从以下角度评审本方案, 每点给 PROCEED/REVISE/BLOCK + 理由 + 修正:
- **理论严谨性**: 形态定义/位置消歧是否符合成熟理论, 有无张冠李戴。
- **可实现性**: 声明式 config + 软隶属 能否表达位置消歧 + 边界事件, 还是需要架构改造。
- **PIT/泄漏**: 上下文消歧(前序态)、边界事件(序列)、确认门(延迟) 的 PIT 安全。
- **覆盖完整性**: 是否真穷尽, 有无遗漏/重叠/留缝。
- **over-fit**: 参数空间膨胀的过拟合风险 + walk-forward 守法。
- **A股适配**: 涨停板/T+1/壳股 等 A股特性对形态识别的影响。
