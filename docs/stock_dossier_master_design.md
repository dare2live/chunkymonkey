## 0. 一句话

给**任一股票**一份多维度可解读的"档案": 它的历史与当下, 从 **形态 / 时间框架 / 板块概念 / 资金 / 筹码 / …** 各维度被量化解读, 维度可无限叠加, 参数是人话且前端可调, 默认按维度列出符合的股票 + 趋势线对比。

```
股票档案 (Stock Dossier)
├── 维度① 形态 technical_states  [已建]   日/周/月 状态(7主态)+子态 + 量化特征
├── 维度② 板块/概念 sector_context [数据就绪] 所属申万行业/东财概念标签 + 板块走势对比(领涨/落后)
├── 维度③ 资金 capital_flow      [数据就绪] 主力净流入/北向/换手 异常
├── 维度④ 筹码 chip_distribution [数据就绪] 筹码集中度/胜率/获利盘/单峰多峰
├── …(可扩展: 基本面/估值/预期上调/龙虎榜/解禁…)  ← 加维度=加一个模块+config, 不动框架
└── 前端 dossier_view                     多维度解读卡 + 趋势线 + 板块对比叠加 + 交互调参(边界耦合同步)
```

## 1. 创世层 (Genesis — 不可变, 极硬)

**为何存在**: 量化选股的前提是"看懂一只股"——不是黑箱模型吐分, 而是人(和下游策略)能从多个可解释维度理解一只股票此刻处于什么状态、相对同类是强是弱、筹码资金在干什么。档案是这套理解的**统一入口与单一计算点**。

**死亡条款 (≤3, 陌生人可判定)**:
1. **感知死**: 任一维度的解读与第一手真相源(K线/资金/筹码原始数据)脱节——形态标错、板块走势用错口径、筹码方向反, 而无人对账。
2. **判断死**: 任一维度的判断规则 hardcode 进代码而非 config——不可调、不可解释、参数不是人话。
3. **谄媚死**: 档案只显示"利好"维度, 藏掉矛盾信号(日线涨但周线破位 / 资金流入但筹码在派发)。诚实呈现冲突 > 给一个干净结论。

## 1.5 信息分层 (用户 2026-06-21: 形态=基础层, 量价资金=第二层)

档案信息分**两层**, 第二层叠在基础层上做**确认/质化**(不独立, 服务于解读基础层形态):

| 层 | 内容 | 角色 |
|---|---|---|
| **基础层 (Layer 1) = 价格形态** | technical_states 形态识别 (9态+子态+上下文+单日K线+命名形态+多TF) | 骨架: 价格走出什么形态 |
| **第二层 (Layer 2) = 量价/资金/筹码** | 成交量/换手率 · 筹码分布/胜率 · 主力资金(明盘)/量价背离/主力意图 · RS相对强度 | 血肉: 确认/质化基础层形态 |

**第二层确认基础层的例子**:
- 基础层"放量突破"(价格形态) ← 第二层"放量+主力净流入+今日看多"**确认**真突破 (vs 缩量假突破)
- 基础层"高位滞涨" ← 第二层"高获利盘+筹码派发+主力净流出"**确认**顶部 (鱼尾出场)
- 基础层"上升通道" ← 第二层"RS强于大盘+主力持续净流入"**确认**主升健康

**口径红线 (reconcile wf_e6a0e9e8 裁决)**: 第二层"主力资金"统一走 `capital.mainforce_net`(=东财 moneyflow_dc.net_amount 大单净)单一真相源; **禁用 tushare net_mf_amount 当主力净额**(=厂商净主动流, 跟中小单/动量, 与主力档常反向)。

**暗盘伪维度裁决 (2026-06-21 measured, sandbox/mingan_redesign; 用户两轮质疑后双向对抗确认)**: 同花顺"暗盘追踪"= L2 逐笔专有产品, **日度 moneyflow 任何口径都无法近似**, 故砍掉伪暗盘公式 (旧 `mingan_flow` 的 X_8×中小单), 资金维度改 **明盘(主力大单净, 89%对齐同花顺明盘) × 价格 量价背离代理**:
- **净额口径 (零和镜像)**: 东财桶 elg+lg+md+sm=0 恒成立 → 中小单净 ≡ −大单净, "暗盘"= 明盘取负零独立信息 (方向一致率 54% 随机)。
- **gross 口径 (96% 假象)**: tushare 标准 moneyflow 中小单 gross 买入 vs 同花顺暗盘方向 96% — 但是假象: 同花顺只发暗盘流入票 (选择偏差) + 中小单买入对活跃股恒为大正数 = 平凡一致; 排序 spearman 0.283 (绝对)/−0.177 (相对) 不相关; 同花顺暗盘票中小买入占比在全市场**低分位** (中位 0.09, 0/25 高分位); 量级比 2.89~63 波动 20x 不可校准。
- **结论**: 真暗盘需 L2 逐笔源 (need_027 BLOCKED, 付费 L2 行情/同花顺暗盘 API); 日度最优诚实代理 = **量价背离** (主力大单流出但价涨=隐性承接吸筹; 流入但价跌=隐性派发), 诚实命名非伪造暗盘金额。
- **主力意图 6象限** (`capital.zhuli_intent`, config 主力意图段): 明盘方向 × 价格方向 → 洗盘低吸/缩量阴跌/诱空吸筹建仓/拉高派发诱多/主力推升看多/主力做空出逃。同花顺暗盘追踪 26 条解读语义保留, 用可靠维度重锚。
- **三因子分离 (用户纪律)**: 明盘/量价背离/主力意图 各独立, 因子层不提前混合 (留给选股层 Optuna 学权重)。

## 2. 核心抽象 — 维度解读器 (DimensionInterpreter)

> 这是"可扩展"的全部秘密: 每个维度是一个实现统一协议的独立模块。加维度 = 写一个新模块 + 一份 config, **框架一行不动**。

每个维度模块 (`backend/services/dossier_dims/<dim>/`) 实现 4 个接口 + 1 份 config:

| 接口 | 人话 | 机器话 (契约) | PIT |
|---|---|---|---|
| `interpret(stock, as_of, tf)` | 这只股此刻在这维度是什么状态/标签/数值 + **人话描述** | `→ {value, label, desc_cn, confidence}` | 只用 ≤as_of |
| `series(stock, tf)` | 这维度的**历史走势(趋势线, 非K线)** | `→ [{date, y, segment_label}]` | 每点只用≤该点 |
| `compare(stock, peers)` | vs 同板块/同类 是强是弱 | `→ {rank_pct, peer_median, lead_lag}` | as-of 同期 |
| `screen(filter, as_of)` | **列出符合某状态的所有股票** (默认视图) | `→ [stock,…]` | 排除股已过 universe |
| config `<dim>.yaml` | 判断阈值/分类规则 = **人话 + 单位** | evaluator 解释执行, 加规则=改 config | judgment→yaml |

**统一红线 (所有维度继承)**: ① 排除股 `services.universe.assert_universe_clean` 硬门; ② PIT(`built_at/as_of_date <= t`); ③ 多时间框架(日主+周/月辅, 窗口按TF缩放); ④ judgment 参数全 config 人话, 禁 hardcode; ⑤ 异常高数字=leakage 警报。

**档案聚合器** `services/dossier.py`: `build_dossier(stock, as_of) → {dim: interpret(...)}`——不是一张大表, 是按需调各维度解读器组装。下游选股 = 把维度 `interpret` 的 value 当条件化因子(接回 `fact_rally_stage` 逐阶段因子矩阵)。

## 3. 判断法典种子 (人话 + 机器话)

| # | 人话 | 机器话 (可执行) |
|---|---|---|
| J1 | 参数是简洁人话, 不是后端变量 | config 用指标中文名+%/倍数单位(`均线斜率 高于 6.5%`), 非 `ma_slope: 0.0655`; 公式结构(条件列表)也进 config |
| J2 | 边界参数互相关联, 调一个要同步并给出变化 | config `边界耦合` 段声明关联(上升退出↔下跌进入); resolver 调一个→同步关联→重算受影响股票列表→报 delta |
| J3 | 默认看到的是"符合这形态的股票列表+趋势线", 不是孤立指标 | `screen()` 返回列表; 前端默认渲染列表 + 每股**趋势线(非K线)** |
| J4 | 维度可无限叠加且互不耦合 | 新维度实现 DimensionInterpreter 协议即接入; 维度间无 import 依赖, 仅在 dossier 聚合层并列 |
| J5 | 一只股可同时部分属多态, 诚实报冲突 | 软隶属度(softmax)+熵; 多维度矛盾(日涨周跌)并列显示不隐藏 |
| J6 | 板块/资金/筹码维度的口径不能混 | 行业=申万 / 概念=东财 / 资金 flow vendor=membership vendor(东财链自洽); 禁同花顺第三套 |

## 5. 前端档案视图 (dossier_view)

技术栈: FastAPI route(`routers/dossier.py`) + 自包含 HTML(同 `design/*.html` 风格, 无 node)。后端 API 出 JSON, 前端渲染。

| 用户要求 | 实现 |
|---|---|
| 股票档案看历史+现在解读 | 顶部股票选择 → 多维度解读卡片(形态/板块/资金/筹码)每张含人话描述 |
| 日/周/月维度解读 | 形态卡内三框 tab; mtf_aligned 高亮 |
| 趋势线非精确K线 | SVG 折线: 收盘趋势 + MA + **状态着色分段**(上升通道绿/下跌红/横盘灰); 不画蜡烛 |
| 默认给符合形态的股票列表+走势 | 左侧形态筛选器 → 右侧符合股票列表, 每行一条 mini 趋势线 |
| 前端调参微调识别 | 参数面板=人话滑块(均线斜率阈值/量比阈值…); 调动→后端实时重 `screen()` |
| 边界参数关联同步 + 给出变化 | 调一个滑块, 关联参数(J2)联动高亮 + 列表 diff(新增/移出哪些股)即时显示 |
| 调整后形态叠加对比 | before(当前参数)/after(调整后)两套趋势线**重叠**, 移出股标灰、新增股标亮 |
| 后续加板块概念标签+板块走势对比 | 维度卡可增, 板块走势线叠加到个股趋势线上对比(领涨/落后) |

## 6. 数据层

- **不建大宽表 fact_stock_dossier**(违奥卡姆+随维度爆列)。档案 = 聚合器**按需实时算 or 各维度独立物化 fact**。
- 各维度若需物化(供选股 join), 各出一张 `fact_<dim>_state`(如 `fact_stock_technical_state`), 档案聚合器 as-of join。
- 物化与否的判据: 前端实时算够快→不物化(形态单股<100ms); 选股要全宇宙×全历史 join→物化(供 `fact_rally_stage` 因子矩阵消费)。
