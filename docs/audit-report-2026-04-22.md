# 综合审计报告（更新版）

日期：2026-04-22

范围：本轮报告覆盖两部分内容：

- 对 2026-04-22 当天最新代码变更的复查。
- 从数据、变量加工逻辑、画像能力边界三个角度，对“机构行为研究 -> 股票画像 -> 跟/不跟决策”主链路做彻底审计。

本报告已整体替换上一版结论，不再沿用此前已经过时的判断。

## 一、执行摘要

当前系统已经能够较稳定地支撑以下目标：

- 研究机构披露持仓行为，而不是机构真实交易行为。
- 对被机构覆盖、且进入当前关系层的股票做画像与排序。
- 以公告后表现为基础，产出“跟 / 观察 / 回避”类决策。

当前系统还不能完整支撑以下目标：

- 研究机构真实建仓时点、执行能力、盘中交易风格。
- 为全市场全部 A 股提供同等质量的股票画像。
- 在行业细分层面稳定识别“机构在哪类股票上真正有 edge”。

本轮复查确认的正向变化：

- `signals_v2` 的回撤列已经改为随 `horizon_days` 映射，不再全部固定到 `max_drawdown_60d`。
- `mart_institution_profile` 已补入通用 `win_rate_120d`，机构画像生成链也已开始写入该字段。
- 机构评分里的 buy / fallback 判定已经改为 per-institution，而不是全局 `has_buy_data`。

本轮仍然成立的高优先级问题：

- 120 日胜率只修到了写层，评分链和解释链仍有读口径未接上。
- “median 回撤”实现仍不严格，偶数样本取的是上中位，不是真正 median。
- `historical_median_holding_days` 在真实库里 231 家机构全部为空，但底层事件数据足够，说明物化结果没有真正产出。
- 机构行业能力统计仍按当前行业归因，历史表现会被当前行业映射重写。
- TDX L3 行业缺失量较大，削弱细分行业画像能力。

## 二、本轮代码变更审查

### 2.1 已确认修复或改善的点

1. `signals_v2` 回撤口径已随 horizon 同步。

- `PolicyConfig.drawdown_column` 已按 `horizon_days` 映射：`<=30d -> max_drawdown_30d`，`>=60d -> max_drawdown_60d`。
- `recommend_for_event()`、`institution_track_record()`、分行业 track record 都已把该列传入 `compute_ev_stats()`。

2. 机构画像已增加通用 `win_rate_120d`。

- `mart_institution_profile` schema 已存在 `win_rate_120d`。
- 机构画像生成函数 `_step_build_profiles_sync()` 已一并计算 `wr120` 并写入。

3. 机构评分的 buy / fallback 样本逻辑已有改善。

- `calculate_institution_scores()` 已改成每家机构单独判断是否有 buy 样本。
- 这避免了“部分机构有 buy、部分机构只能 fallback”时全体统一按 `buy_event_count` 排样本量的问题。

### 2.2 本轮仍未闭环的问题

1. 120 日胜率在评分链和解释链没有完全接上。

- `backend/services/scoring.py` 的查询仍只选到 `win_rate_90d`，但后续 fallback 逻辑已经改成取 `win_rate_120d`。
- `backend/services/institution_scoring_read.py` 的因子展示已经按 120 日解释，但其加载查询仍未把 `win_rate_120d` 取出来。

这会导致：

- schema 和画像写层已经有 120 日胜率。
- 评分链与解释链却未稳定消费该字段。

这是本轮最明确的“写层已修，读层未完全闭环”的问题。

2. “median 回撤”实现仍不严格。

- 当前 `median_max_drawdown_30d/60d` 已不再用 `AVG()`，而是改成 Python 端排序后取中间值。
- 但偶数样本时直接取 `len(vals) // 2`，这会得到上中位，而不是严格意义上的 median。

影响：

- 问题已从“均值冒充中位数”收敛到“偶数样本中位数实现不准确”。
- 这仍会进入机构回撤控制分和解释文案，不建议继续按“中位数”命名对外使用。

3. `historical_median_holding_days` 仍未产出有效值。

- 构建机构画像时，代码确实在按 `new_entry.notice_date -> exit.notice_date` 计算闭合持有周期。
- 但真实库里 `mart_institution_profile.historical_median_holding_days` 当前 231 家机构全部为空。
- 同时，真实库里有 1174 条 `exit` 事件、15009 条 `new_entry` 事件、1131 个 institution-stock 对同时存在 entry 和 exit。

结论：

- 这不是“没有底层数据”。
- 更可能是聚合逻辑或写回结果没有真正落到 mart。

### 2.3 新增脚本审查

1. `scripts/train_phase3a.py`

该脚本注释写的是“行业 one-hot 开 / 关两组对照训练”，但实现里只跑了 `use_industry_onehot=True` 一组，没有对照组。

当前状态下，它还不能支持“开关对比”的实验结论，只能算单臂训练脚本。

2. `analyze_coverage.py`

该脚本直接复制了一整份 TDX 行业字典，并读取 `data/smartmoney.db` 做覆盖分析。

问题不在于功能，而在于它复制了行业字典真相源；如果主字典更新，这个脚本会静默漂移。

3. `parse_tdx.py`

该脚本通过正则直接解析 `backend/services/tdx_industry_names.py` 源文件文本，再输出 branch/leaf L2 列表。

问题：

- 它不是读取共享模块或共享常量，而是在“解析源码文本”。
- 这是一类明显的临时分析脚本，不应长期作为稳定工具链的一部分。

## 四、数据能否实现项目目标

### 4.1 能实现的目标

当前数据足以支撑以下研究问题：

- 哪些机构在披露后的 30 / 60 / 120 日窗口里更容易带来正收益。
- 哪些机构更适合“低溢价跟随”。
- 机构覆盖过、且仍处于当前关系层的股票里，哪些股票更值得进入研究池或观察池。
- 在“机构最近公告 -> 股票当前状态 -> 历史同类事件表现”框架下做公告后跟随决策。

### 4.2 当前数据不能完整回答的问题

以下问题现有数据无法完整支撑：

- 机构真实建仓时点是什么。
- 机构建仓后的盘中执行质量如何。
- 机构是提前埋伏、追涨确认，还是临近披露才开始进入。
- 机构风格是否稳定跨越多个完整行业周期。

原因不是模型不足，而是底层数据粒度决定的：

- `fact_institution_event` 的事件来自持仓披露数据与相邻报告期差分。
- `exit` 也是通过“上一期有、最新期无”推断，而不是交易回报系统直接记录。

因此，这套系统研究的是“披露持仓行为”，不是“真实交易行为”。

## 五、变量加工逻辑审计

### 5.1 机构画像变量

当前机构画像中，最可靠的变量是：

- `gain_30d/60d/120d`
- `max_drawdown_30d/60d`
- `premium_pct`
- `follow_gate`
- `buy_win_rate_*`
- `safe_follow_*`

这些变量多数直接来自 `fact_institution_event` 或由其单点聚合而来，方向是对的。

当前机构画像中，逻辑上偏弱或未闭环的变量是：

1. `signal_transfer_efficiency_30d`

- 本质是 `safe_avg_gain_30d / buy_avg_gain_30d`。
- 它不是原始事实，而是二次比值，且只在 buy 均值为正时才有意义。
- 更适合作为辅助解释，不适合作为稳定主特征。

2. `historical_median_holding_days`

- 理论上是非常重要的机构风格变量。
- 但当前库里 0% 非空，等于尚未真正进入画像体系。

3. `current_stock_count`、`current_avg_held_days`

- 它们是当前快照变量，不是长期风格变量。
- 可以描述“当前状态”，不能直接替代“机构长期风格”。

### 5.2 股票画像变量

当前股票画像主要由四组分数组成：

- `discovery_score`
- `company_quality_score`
- `stage_score`
- `forecast_score`

这四组变量的含义并不完全对称。

1. `discovery_score`

- 更像“机构发现强度 + 披露新鲜度 + 持仓强度 + 方向性”的组合分。
- 它反映的是“机构研究热度与确认度”，不是股票本体的长期股性。

2. `company_quality_score`

- 质量分对企业体质有一定解释力。
- 但它仍然是财务快照型变量，本质更新频率低于价格与行为变量。
- 当前快照日期为 2026-04-17，且质量维行数高于 active 股票数，说明它覆盖的是更宽的历史/全量股票池，不等于当前研究主池。

3. `stage_score`

- 阶段分是当前最强的“执行辅助变量”之一。
- 但它明显偏当前状态，受近期价格、路径和行业上下文影响大。
- 它适合做“当前是否适合跟”，不适合单独当成长期股性画像。

4. `forecast_score`

- 当前既包含预测特征，也可能 fallback 到 `qlib_percentile` 或默认中性值。
- 由于 Qlib 仅覆盖 898 只股票，且 `predict_date` 落后，因此这一维当前还不能视为稳定主画像层。

### 5.3 变量层最重要的边界

当前股票画像更准确的定义应是：

- “机构覆盖股票的研究优先级画像”

而不是：

- “股票自身完整股性的统一真相画像”。

原因：

- 研究对象先被 `mart_current_relationship` 筛过一遍。
- 之后才进入 `mart_stock_trend`、quality / stage / forecast / turtle 的融合。
- 因此这套画像天然带有“机构先验触达”的样本偏差。

## 六、与项目目标的匹配度判断

### 6.1 当前最适合的项目定位

如果按现有数据与逻辑的真实能力来定义，项目最适合的定位是：

- 机构披露行为研究系统
- 机构覆盖股票研究系统
- 公告后跟随决策系统

### 6.2 当前不宜过度承诺的定位

当前不宜直接对外宣称：

- 已经研究透机构真实交易行为
- 已经完成全市场股票股性画像
- 已经具备细分行业级、全量股票级、统一真相源的决策系统

这不是否定项目，而是要求定义更精确，避免变量承载超出其数据来源能力的含义。

## 七、优先整改顺序

### P0

1. 补齐 `win_rate_120d` 在评分链和解释链的读取闭环。
2. 把 `median_max_drawdown_*` 改成真正 median，或全链路更名为别的统计量。
3. 查清 `historical_median_holding_days` 为什么 0% 非空，并修复物化结果。

### P1

1. 明确 UI 和文档口径：当前系统研究的是披露行为，不是真实交易行为。
2. 明确股票画像边界：当前是机构覆盖股票画像，不是全市场画像。
3. 对当前行业归因增加显式标注，避免把“当前行业口径”误解为“历史行业口径”。

### P1

1. 补强 L3 行业覆盖，或在细分行业分析里显式降级到 L2。
2. 明确 forecast / Qlib 的角色：是增强因子，不是全覆盖主特征。

### P2

1. 清理单次分析脚本与重复真相源脚本。
2. 若继续做 `train_phase3a`，补上真正的 on/off 对照训练与结果落表。
3. 为本轮暴露出的读链问题、holding-days 物化问题补测试。

## 八、最终判断

项目当前并不是“到处各算各的、完全失控”。主事实层与主聚合层已经形成了可用骨架，且这轮代码变更已经继续朝“收口真相源、修复口径”方向前进。

但从“把机构行为研究透，再把股票股性画像，再做跟 / 不跟决策”这个更高目标看，当前最大的约束已不再是单点 bug，而是边界问题：

- 数据研究的是披露行为，不是真实交易行为。
- 股票画像研究的是机构覆盖池，不是全市场。
- 行业细分与持有周期两个关键画像维度还没有稳定落地。

因此，下一阶段最重要的工作不是继续往上叠更多新分数，而是先把以下三件事做实：

- 把已经补入的数据字段真正接到评分链和解释链。
- 把无效或未产出的画像变量修好，或者先降级出主路径。
- 把系统目标、数据边界、变量含义在代码、UI、文档三层统一下来。
