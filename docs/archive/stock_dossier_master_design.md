## 1. 创世层 (Genesis — 不可变, 极硬)

**为何存在**: 量化选股的前提是"看懂一只股"——不是黑箱模型吐分, 而是人(和下游策略)能从多个可解释维度理解一只股票此刻处于什么状态、相对同类是强是弱、筹码资金在干什么。档案是这套理解的**统一入口与单一计算点**。

**死亡条款 (≤3, 陌生人可判定)**:
1. **感知死**: 任一维度的解读与第一手真相源(K线/资金/筹码原始数据)脱节——形态标错、板块走势用错口径、筹码方向反, 而无人对账。
2. **判断死**: 任一维度的判断规则 hardcode 进代码而非 config——不可调、不可解释、参数不是人话。
3. **谄媚死**: 档案只显示"利好"维度, 藏掉矛盾信号(日线涨但周线破位 / 资金流入但筹码在派发)。诚实呈现冲突 > 给一个干净结论。

## 1.5 信息分层 (用户 2026-06-21 三层: 形态 / 每日盘面 / 会变属性; 经 4视角Workflow+3lens对抗定稿)

档案信息分**三层**, 上层叠在下层做**确认/质化/解释** (不独立, 服务于解读形态):

| 层 | 内容 | 角色 | 分层判据 (用户"更新频率" × 因果"内生外生" 融合) |
|---|---|---|---|
| **第一层 = 价格形态** [已完成] | technical_states (9态+子态+上下文+单日K线+命名形态+多TF) | 骨架: 价格走出什么几何形态 | 纯 OHLCV 价格序列算出的几何 |
| **第二层 = 每日盘面行为** [部分] | 成交量/量比 · 换手率 · 主力大单净/量价背离/主力意图 · 筹码分布/胜率 · RS相对强度 · 个股vs板块领涨落后 | 血肉: 确认形态真伪 (放量突破←主力净流入=真) | **每日更新**的本股量价/资金/筹码**数值流** (内生, PIT t-1 盘后) |
| **第三层 = 属性/分类/背景** [待建] | 板块/概念/行业 · 基本面(财报) · 估值(PE/PB) · 分析师预期 · 事件催化(龙虎榜/大宗/解禁/股东户数/机构调研) · 市场环境regime门 | 灵魂: 为什么涨 + 可持续性/燃料 | **慢变/会调整**的外部属性 (外生, PIT锚 ann_date/事件日) |

**边界判据 (用户"每日更新vs会变" 与 因果"内生vs外生" 一致)**:
- **L1↔L2**: 价格几何**本身** vs 价格几何的**真伪确认** (量价资金叠加)。成交量是边界物——vol_ratio 已被 L1 features 用作放量突破内部判据, 但量作为独立确认维度归 L2 (L1内部用/L2独立成维, 双栖不矛盾)。
- **L2↔L3**: 本股**每日量价行为** (内生数值流, 每日刷新) vs 外部**属性/分类/驱动** (外生, 慢变或归属会调整)。
  - **daily_basic 整表跨层须按字段拆**: 换手率/量比→L2, PE/PB/PS/市值→L3 (否则估值背书误当形态确认=leakage 隐患)。
  - **板块数据按用途拆**: 个股vs板块"领涨/落后"相对位置→L2; 板块自身 regime/资金轮动→L3。

**确认/解释链例子 (三层叠加)**:
- L1"放量突破" ← L2"放量+主力净流入"确认真突破 ← L3"业绩加速+板块风口"解释可持续 (vs 纯题材投机)
- L1"高位滞涨" ← L2"高获利盘+筹码派发+主力净流出"确认顶部 ← L3"解禁临近+估值高位"强化鱼尾出场
- L1"上升通道" ← L2"RS强于大盘+主力持续净流入"确认主升健康 ← L3"机构调研增+分析师上调"解释驱动

**三因子分离 + regime门 (Workflow 3lens对抗裁决)**: L3 的市场环境/regime = **横切门 (gate)** 不是单股因子——选股层用作 stage-conditional 最外层条件 (先过regime门再阶段内排名), 三因子分离下留 Optuna 学权重, 不与个股因子提前混合。北向(个股已停披露 ~2025-07)仅历史, 不进 L2 个股链。stk_factor_pro 261列不进档案(非人话维度), 旁挂选股层因子池。

**口径红线 (reconcile wf_e6a0e9e8 裁决)**: 第二层"主力资金"统一走 `capital.mainforce_net`(=东财 moneyflow_dc.net_amount 大单净)单一真相源; **禁用 tushare net_mf_amount 当主力净额**(=厂商净主动流, 跟中小单/动量, 与主力档常反向)。

**暗盘伪维度裁决 (2026-06-21 measured, sandbox/mingan_redesign; 用户两轮质疑后双向对抗确认)**: 同花顺"暗盘追踪"= L2 逐笔专有产品, **日度 moneyflow 任何口径都无法近似**, 故砍掉伪暗盘公式 (旧 `mingan_flow` 的 X_8×中小单), 资金维度改 **明盘(主力大单净, 89%对齐同花顺明盘) × 价格 量价背离代理**:
- **净额口径 (零和镜像)**: 东财桶 elg+lg+md+sm=0 恒成立 → 中小单净 ≡ −大单净, "暗盘"= 明盘取负零独立信息 (方向一致率 54% 随机)。
- **gross 口径 (96% 假象)**: tushare 标准 moneyflow 中小单 gross 买入 vs 同花顺暗盘方向 96% — 但是假象: 同花顺只发暗盘流入票 (选择偏差) + 中小单买入对活跃股恒为大正数 = 平凡一致; 排序 spearman 0.283 (绝对)/−0.177 (相对) 不相关; 同花顺暗盘票中小买入占比在全市场**低分位** (中位 0.09, 0/25 高分位); 量级比 2.89~63 波动 20x 不可校准。
- **结论**: 真暗盘需 L2 逐笔源 (need_027 BLOCKED, 付费 L2 行情/同花顺暗盘 API); 日度最优诚实代理 = **量价背离** (主力大单流出但价涨=隐性承接吸筹; 流入但价跌=隐性派发), 诚实命名非伪造暗盘金额。
- **主力意图 6象限** (`capital.zhuli_intent`, config 主力意图段): 明盘方向 × 价格方向 → 洗盘低吸/缩量阴跌/诱空吸筹建仓/拉高派发诱多/主力推升看多/主力做空出逃。同花顺暗盘追踪 26 条解读语义保留, 用可靠维度重锚。
- **三因子分离 (用户纪律)**: 明盘/量价背离/主力意图 各独立, 因子层不提前混合 (留给选股层 Optuna 学权重)。

## 2. 核心抽象 — 维度解读器 (DimensionInterpreter)

> 这是"可扩展"的全部秘密: 每个维度是一个实现统一协议的独立模块。加维度 = 写一个新模块 + 一份 config, **框架一行不动**。

每个维度模块 (`backend/services/dossier_dims/<dim>/`) 实现 4 个接口 + 1 份 config:

| 接口 | 人话 | 机器话 (契约) | PIT |
|---|---|---|---|
| `interpret(stock, as_of, tf)` | 这只股此刻在这维度是什么状态/标签/数值 + **人话描述** | `→ {value, label, desc_cn, confidence}` | 只用 ≤as_of |
| `series(stock, tf)` | 这维度的**历史走势(趋势线, 非K线)** | `→ [{date, y, segment_label}]` | 每点只用≤该点 |
| `compare(stock, peers)` | vs 同板块/同类 是强是弱 | `→ {rank_pct, peer_median, lead_lag}` | as-of 同期 |
| `screen(filter, as_of)` | **列出符合某状态的所有股票** (默认视图) | `→ [stock,…]` | 排除股已过 universe |
| config `<dim>.yaml` | 判断阈值/分类规则 = **人话 + 单位** | evaluator 解释执行, 加规则=改 config | judgment→yaml |

**统一红线 (所有维度继承)**: ① 排除股 `services.universe.assert_universe_clean` 硬门; ② PIT(`built_at/as_of_date <= t`); ③ 多时间框架(日主+周/月辅, 窗口按TF缩放); ④ judgment 参数全 config 人话, 禁 hardcode; ⑤ 异常高数字=leakage 警报。

**档案聚合器** `services/dossier.py`: `build_dossier(stock, as_of) → {dim: interpret(...)}`——不是一张大表, 是按需调各维度解读器组装。下游选股 = 把维度 `interpret` 的 value 当条件化因子(接回 `fact_rally_stage` 逐阶段因子矩阵)。

## 6. 数据层
